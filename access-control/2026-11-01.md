# Access Control（横の権限昇格編） — 2026-11-01

## 解いたラボ
### User ID controlled by request parameter, with unpredictable user IDs（IDOR）✅
- carlos の GUID はランダムで直接は分からない。
- ブログのコメント欄に carlos が登場 → そこから carlos の GUID を入手（隠しIDが漏れていた）。
- 自分(wiener)のログイン済みページを土台に、URLの id= を carlos の GUID に書き換え。
- carlos の API Key が表示された → 提出して解決。

### User ID controlled by request parameter with password disclosure（横→縦）✅
- `/my-account?id=administrator` でアクセス。
- ページの中に、マスクされた input に administrator のパスワードが prefill されていた（value=... で丸見え）。
- そのパスワードで administrator としてログインし直し → 管理機能で carlos 削除。

## 自分の言葉での理解
- 横（horizontal）の権限昇格 = 同じ立場の他人になりすます。縦（vertical）= 上の権限を取る。
- IDOR = ユーザーが触れる値（id）で直接リソースを指定させて、権限チェックしてない。前回の Admin=true と同じ骨格。
- 「IDを推測しにくくする（GUID）」は対策にならない。どこか（コメント・レビュー）に漏れている。
- 攻撃の基本手順：自分の正規アクセスを土台に、id を他人のに差し替える。
- wiener:peter が与えられるのは「攻撃の駒」ではなく「正常な流れを観察する見本」。
  まず自分で正常系を見てから、他人で穴を突く（偵察が先）。

## IDOR が実戦で重要な理由
- 特別な技術が要らない（id を1個変えるだけ）→ 開発者も見落とす → バグバウンティ報告件数トップクラス。
- credential stuffing（漏洩パスワードの使い回しを突く）と並んで、被害の大半を占める。
