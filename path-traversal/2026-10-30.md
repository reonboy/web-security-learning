# Path Traversal（パストラバーサル） — 2026-10-30

## このトピックは何か
サイトが「フォルダ名 + ユーザーが送ったファイル名」でファイルを読むとき、
ファイル名に `../` を混ぜると、本来のフォルダの外に出て、好きなファイルを読める脆弱性。
path = 道、traversal = 横断。

## 解いたラボ
### File path traversal, simple case（APPRENTICE）✅
- 画像読み込みの通信 `GET /image?filename=39.jpg` が注入ポイント。
- `filename` を `../../../etc/passwd` に書き換えて送信 → `/etc/passwd` の中身が返ってきた。
- Burp の Proxy で画像の通信を見つけ、Repeater に送って書き換え・送信。

## 自分の言葉での理解
- サーバー内のファイルは `/var/www/images/39.jpg` にある。
- `../` は「1つ上のフォルダに戻る」。`images → www → var → /（ルート）` で3回戻ればルートに着く。
- ルートから `etc/passwd` に入れるので、`../../../etc/passwd` で読めた。
- `/etc/passwd` は Linux のユーザー情報ファイル。読めたら攻撃成功の定番の証拠。
- `/var` は variable（変わるデータ、ログやWebサイト置き場）、`/etc` は設定ファイル置き場。
  Windowsで育つと見ないので知らなかったが、Webサーバーの多くはLinux。

## 対策（甘い対策 vs 本物の対策）
| | 見ているもの | 強さ |
|---|---|---|
| 甘い対策 | 入力の「書き方」（`../` を探して消す） | 書き方を変えられると破られる |
| 本物① | そもそも入力をファイル読み込みに使わない（番号方式） | 攻撃の入口がない |
| 本物② | 正規化して「最終的な行き先」を見て、imagesの外なら拒否 | 書き方に関係なく止まる |

- 甘い対策が破られやすいのは、防御側は危険パターンを全部列挙しないといけないが、
  攻撃側は1個でも抜け道を見つければ勝ち、という非対称があるから。
- 例：`....//` → `../` を1回消すと復活。`..%2f` → 後でサーバーが `/` に戻すと `../` になる。
- SQLi の「`'` を消す」より「プリペアドステートメント」が強いのと、まったく同じ構造。
  → 「探して消す」は弱い、「仕組みで封じる」が強い。分野をまたいで同じ原理。
