# SSRF（サーバーサイドリクエストフォージェリ） — 2026-11-01

## このトピックは何か
サーバーを「操り人形」にして、あなたが直接届かない場所へ、サーバーに代わりにアクセスさせる攻撃。
今までは自分で直接攻撃 → SSRF はサーバーを踏み台にして内側（ファイアウォールの中）に手を伸ばす。

## なぜ成立するか
- サーバー自身（localhost）や内部ネットワークからのアクセスは「信頼できる」と油断されがち。
- 理由：チェック役が正面玄関にしかいない／災害復旧用の裏口（内部ならログイン不要）／管理画面が別ポートで隠れている。
- 「中から来た＝信頼できる」という思い込みを、サーバーを操って突く。

## 解いたラボ
### SSRF against the server（localhost） ✅
- 在庫確認機能 stockApi=http://... のURLを書き換え。
- stockApi=http://localhost/admin → サーバー自身の管理画面が返る（外部の自分は門番に弾かれるが、サーバー経由なら通る）。
- stockApi=http://localhost/admin/delete?username=carlos → carlos 削除。

### SSRF against internal back-end（IPスキャン） ✅
- stockApi=http://192.168.0.§X§:8080/admin で X を Intruder で総当たり。
- Payload type = Numbers（From 0, To 255, Step 1）で IP の最後の数字をスキャン。
- Status 200 が返った1個が管理画面のある内部IP → そこで carlos 削除。
- ※ §§ を付け忘れると同じIPを繰り返すだけで失敗する（ハマった点）。

## 自分の言葉での理解
- localhost / 127.0.0.1 = 「自分自身」の住所（全部同じ意味）。
- プライベートIP（192.168.x.x / 10.x.x.x / 172.16-31.x.x）= 外から直接届かない内部専用の住所。
- ポート = マシンの「何番の入り口か」。管理画面は :8080 など別の入り口に隠れがち。
- IPの各ブロックは必ず 0〜255（8ビット）。だから 0〜255 を全部試せば取りこぼし無し。
- たとえ：内部ネットワーク＝マンション。localhost＝自分の部屋、192.168.0.X＝同じマンションの別の部屋。
  使い（サーバー）は住人なので全部屋に行けるが、部外者（自分）はどこにも直接入れない → 使いに頼む。

## 駐車場
- SSRF のフィルタ回避（127.0.0.1 → [::1]、エンコード、別表記）
- 乗っ取ったサーバーからの pivot（踏み台にして奥へ）
